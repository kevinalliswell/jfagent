# AGENTS.md

This file is the working agreement for Codex and other AI coding agents on this project.

## Project Mission

Build a Data Center Pre-sales AI Agent for construction integration teams. The current implementation is a local-first MVP, but the long-term product direction is SaaS. The product should help sales and pre-sales staff turn messy WeChat-style project descriptions, internal knowledge, historical proposals, and equipment documents into a structured, editable, quote-ready requirement sheet and eventually a polished Word export.

The agent should behave like a senior Chinese data center pre-sales director: practical, commercially aware, fluent in machine-room construction language, and focused on reducing friction rather than asking long forms.

## Required Reading Before Any Task

Before starting a new task, read these files in order:

1. `AGENTS.md`
2. `docs/tasks.md`
3. `docs/architecture.md`
4. `docs/decisions.md`
5. The most relevant specification file for the task:
   - `agents.md` for conversation/FSM/product behavior.
   - `rules.md` for calculation and expert risk rules.
   - `knowledge_base.md` for RAG ingestion and retrieval policy.
   - `templates.md` for Word/proposal rendering rules.
   - `api_spec.md` for backend API contracts.
   - `LOCAL_RAG.md` for current local knowledge indexing behavior.

## Development Flow

For each task:

1. Read the required project context.
2. Confirm the concrete task objective and constraints.
3. Make a short implementation plan for non-trivial work.
4. Implement the smallest coherent change.
5. Run the relevant verification command.
6. Update `docs/tasks.md` when task status or priorities change.
7. Update `docs/architecture.md`, `docs/tech-stack.md`, or `docs/decisions.md` when the design changes.
8. Summarize what changed, how it was verified, and what remains.

## Scope Control

Do not start feature implementation until project planning, architecture, and task state are clear. If the user asks for planning or initialization work, prioritize documentation and alignment over code.

Keep changes tightly scoped. Avoid broad refactors unless the current task explicitly requires them or the existing structure blocks safe progress.

## Source Of Truth

Current project source files:

- `src/` contains the React/Vite frontend prototype.
- `scripts/` contains local knowledge ingestion utilities.
- `knowledge/` contains seed local knowledge files.
- `src/generatedKnowledge.ts`, `server/generatedKnowledge.ts`, and `server/generatedKnowledge.json` are generated by `npm run kb:build`; do not edit them by hand.
- `agents.md`, `rules.md`, `knowledge_base.md`, `templates.md`, and `api_spec.md` are domain/specification references.
- `docs/` contains long-term project planning and architecture memory.

## Product Guardrails

- Prefer chat plus chips over large forms.
- Keep dashboard edits as the highest-precedence source of truth.
- Clearly distinguish confirmed values from inferred values.
- Do not overwrite `dashboard_edit` values without explicit user confirmation.
- Keep local knowledge citations visible when generated content depends on retrieved context.
- Treat the 99 RMB flow as payment-willingness validation only. Do not implement real payment unless the product decision changes.

## Technical Guardrails

- Use TypeScript types as contracts between UI, mock API, and future backend.
- Keep generated knowledge separate from handwritten code.
- Run `npm run build` before handing off changes that touch frontend or ingestion behavior.
- Run `npm run kb:build` after changing `knowledge/`, `scripts/build-knowledge-index.mjs`, or document extraction scripts.
- Preserve the current local-first MVP path while designing module boundaries so they can evolve into a SaaS backend.

## Documentation Guardrails

Update documentation when:

- A module boundary changes.
- A new dependency or runtime is added.
- A major feature enters or leaves scope.
- A technical decision is made or reversed.
- A task is completed, blocked, or reprioritized.

Prefer concise, living documents over exhaustive static prose. Docs should help the next Codex session resume accurately.
